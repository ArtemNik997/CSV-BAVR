# CSV-driven Browser Automation Video Recorder and Parser

Для каждой строки входного CSV инструмент (Python + Playwright) записывает видео автоматизированных действий в браузере: открывает DuckDuckGo, плавно ведёт курсор к полю поиска, посимвольно вводит запрос `Magento developer in <City>`, нажимает поиск и кликает по первому результату. В видео добавлены SVG-курсор, подсветка, ripple при кликах и callout с текстом.

Во время записи сценарий (или оператор клавишей F5) отмечает моменты зума. Записанные видео можно загрузить на веб-сервис, а он применяет к ним плавный zoom в стиле Camtasia (ffmpeg) и сохраняет результат.

Сервис (Flask + Apache/mod_wsgi), ffmpeg и база данных (PostgreSQL) работают в Docker-контейнерах и запускаются вместе через Docker Compose.

## Архитектура

| Часть                                       | Где работает        | Назначение                                                         |
| ------------------------------------------- | ------------------- | ------------------------------------------------------------------ |
| Рекордер (`capture_video.py`, `qscript.py`) | на вашем компьютере | запись видео и zoom-событий, загрузка на сервис, предпросмотр      |
| `apply_zoom.py`                             | компьютер и `web`   | применение zoom к видео через ffmpeg (CLI и модуль для сервиса)    |
| `web`                                       | контейнер           | Apache + mod_wsgi, Flask-сервис видео, ffmpeg, порт `8000` -> `80` |
| `db`                                        | контейнер           | PostgreSQL 16, таблица `videos`                                    |

Тома: `db_data` (данные PostgreSQL) и `uploads` (загруженные и обработанные видео). Они сохраняются при перезапуске контейнеров.

## Запуск веб-сервиса и БД в Docker

Требуется Docker и Docker Compose v2.

```
docker compose up --build
```

Сервис доступен на `http://localhost:8000`. Остановка: `Ctrl+C` или `docker compose down`. После изменения кода сервиса запускайте с `--build`.

Пароль и имя базы по умолчанию (`video_user` / `video_pass` / `videos`) подходят для учебного запуска. Для своих значений:

```
cp .env.example .env
```

и измените значения в `.env`. Файл `.env` в Git не коммитится.

| Переменная (`.env`) | По умолчанию | Назначение                                                                    |
| ------------------- | ------------ | ----------------------------------------------------------------------------- |
| `POSTGRES_DB`       | `videos`     | имя базы                                                                      |
| `POSTGRES_USER`     | `video_user` | пользователь                                                                  |
| `POSTGRES_PASSWORD` | `video_pass` | пароль                                                                        |
| `AUTO_PROCESS`      | `1`          | обрабатывать видео автоматически после загрузки (0 — только по запросу)       |
| `ZOOM_WORKERS`      | `1`          | потоков обработки на каждый из двух процессов mod_wsgi (до двух ffmpeg сразу) |
| `ZOOM_TIMEOUT`      | `900`        | лимит одного запуска ffmpeg, секунд                                           |

Из этих значений Compose передаёт контейнеру `web` настройки подключения `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASSWORD`. В коде они не заданы. Путь к ffmpeg (`FFMPEG_BIN=/usr/bin/ffmpeg`) задан в образе.

**Данные и тома**

- `docker compose down` — контейнеры удаляются, данные и видео **сохраняются**.
- `docker compose down -v` — тома удаляются вместе с данными.
- Пароль из `.env` применяется только при первой инициализации пустого тома `db_data`. После смены пароля на существующей БД выполните `docker compose down -v` (данные будут удалены).

**Готовность БД.** `web` стартует только после успешной проверки `db` (`healthcheck`, `depends_on: service_healthy`). Дополнительно `init_db()` до 60 раз (с паузой 2 с) пробует подключиться, создаёт таблицу `videos` и добавляет недостающие колонки в уже существующую таблицу (данные при этом не теряются).

## Эндпоинты

| Метод и путь                                 | Назначение                                                                                                                                                                          |
| -------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST /upload`                               | multipart-форма: `file`, `company_name` и необязательное `zoom` (JSON-сайдкар, до 1 МБ). Ответ: `{"company_name", "video_url", "id", "process_status"}`. Некорректный сайдкар — 400 |
| `GET /get_video_url?company_name=<название>` | `{"company_name", "video_url", "process_status", "processed_video_url"}`, 404 если компании нет                                                                                     |
| `GET /media/<путь>`                          | видеофайл, в том числе `processed/<имя>.webm` (отдаёт Apache, поддерживает перемотку)                                                                                               |
| `GET /videos`                                | список всех записей (для отладки), включая статус и URL обработанного видео                                                                                                         |
| `POST /jobs/<id>/process`                    | запустить (или повторить) обработку: 202 — задача поставлена, 409 — уже в очереди или идёт, 404 — записи нет                                                                        |
| `GET /jobs/<id>`                             | `{"id", "company_name", "status", "error", "processed_video_url"}`, 404 если записи нет                                                                                             |

`id` задачи равен `id` записи в таблице `videos`.

Повторная загрузка той же компании обновляет запись и файл, дубликаты не создаются, а результат прежней обработки сбрасывается. Время в БД хранится в UTC (`TIMESTAMPTZ`).

```
curl -F "file=@video/Gamma SARL.webm" -F "company_name=Gamma SARL" -F "zoom=@video/Gamma SARL.webm.zoom.json" http://localhost:8000/upload
curl "http://localhost:8000/get_video_url?company_name=Gamma%20SARL"
curl http://localhost:8000/jobs/1
curl -X POST http://localhost:8000/jobs/1/process
```

В PowerShell используйте `curl.exe`.

`1` в `/jobs/1` — это `id` из ответа на `POST /upload`. Повторный запуск обработки (`POST /jobs/<id>/process`) возвращает 202, если задача поставлена, 409, если она уже в очереди или идёт, и 404, если записи нет.

**Postman**

- `POST /upload`: Body → `form-data`: `file` (тип File), `company_name` (Text), необязательно `zoom` (File). Заголовок `Content-Type` не задавайте, Postman поставит его сам.
- `GET /get_video_url`: в Params ключ company_name.
- `GET /jobs/{id}`: статус обработки.
- `POST /jobs/{id}/process`: Body пустое (`none`).

**Статусы обработки (`status` / `process_status`)**

| Статус       | Значение                                                             |
| ------------ | -------------------------------------------------------------------- |
| `none`       | обработка не запускалась (нет сайдкара или `AUTO_PROCESS=0`)         |
| `pending`    | задача в очереди                                                     |
| `processing` | ffmpeg работает                                                      |
| `done`       | готово, `processed_video_url` заполнен                               |
| `failed`     | ошибка, причина в поле `error`; повторить: `POST /jobs/<id>/process` |

## Zoom-эффект

Zoom — это постэффект: Playwright записывает видео с фиксированным масштабом, поэтому во время записи сохраняются только **события** `{t, x, y, type}`, а само приближение рисуется после записи.

### Как это работает

1. **Захват.** Первое нажатие F5 (или вызов `window.__zoomAt(x, y)` из сценария) отмечает начало приближения (`in`) в текущей позиции курсора, второе — начало отдаления (`out`). Время `t` отсчитывается от начала записи видео.
2. **Сайдкар.** События сохраняются рядом с видео в файле `<видео>.webm.zoom.json`.
3. **Обработка.** `apply_zoom.py` (локально или на сервере) читает сайдкар и фильтром ffmpeg `zoompan` строит плавное приближение: разгон → удержание → возврат.

Правила:

- Центр зума — позиция курсора **в момент события `in`**. Зум не следует за курсором, координаты события `out` не используются.
- Кроп всегда остаётся внутри кадра: у края экрана центр сдвигается.
- Параметры: увеличение 2.0×, разгон и возврат по 0.5 с, плавное ускорение и торможение (easing), 25 кадров/с.
- Пары `in` / `out` могут повторяться и не пересекаются. Если следующий `in` пришёл раньше, чем закончился предыдущий возврат, он сдвигается.
- Если `in` не имеет `out` (запись закончилась в зуме), зум держится до конца видео.
- Если сайдкара нет или в нём нет событий, видео копируется без изменений.
- Выход — `.webm` (VP9) с тем же разрешением, что и вход.

### Захват при записи

- **F5** работает только в режиме с окном браузера и только когда окно активно. В headless клавиатуры нет, используйте `__zoomAt`. F5 не перезагружает страницу.
- При каждом переключении на экране кратко появляется кольцо: зелёное — приближение, красное — отдаление. Оно попадает и в видео.
- **Сценарий** по умолчанию вызывает `__zoomAt` четыре раза: приближение на поле поиска, отдаление после набора запроса, приближение на первом результате и отдаление после перехода.
- Сайдкар пишется **только если есть хотя бы одно событие**. Устаревший сайдкар от прошлого запуска удаляется.

Формат сайдкара:

```json
{
  "viewport": { "width": 1280, "height": 720 },
  "fps": 25,
  "zoom_factor": 2.0,
  "ramp_sec": 0.5,
  "events": [
    { "t": 3.0, "x": 640, "y": 360, "type": "in" },
    { "t": 8.0, "x": 640, "y": 360, "type": "out" }
  ]
}
```

Старые сайдкары без поля `type` поддерживаются: типы чередуются, первое событие `in`.

Если зум в готовом видео идёт с постоянным сдвигом по времени, поправьте `ZOOM_TIME_OFFSET` (секунды) в начале `qscript.py`.

### Автоматический и ручной режим зума

Зум переключается одним общим тумблером: и сценарий (`__zoomAt`), и клавиша F5 меняют одно и то же состояние `in` / `out`. Поэтому используйте **один** режим за запись.

| Режим                         | Как включить          | Что происходит                                                                                  |
| ----------------------------- | --------------------- | ----------------------------------------------------------------------------------------------- |
| Автоматический (по умолчанию) | запускайте как обычно | сценарий сам делает приближение на поле поиска и на первом результате. F5 не нажимайте          |
| Ручной                        | `QS_AUTO_ZOOM=0`      | сценарий зум не трогает, вы нажимаете F5 сами: первое нажатие — приближение, второе — отдаление |

В ручном режиме зум держится столько, сколько прошло между двумя нажатиями. Клавишу **не нужно удерживать**: автоповторы игнорируются, нужны два отдельных нажатия. Окно браузера должно быть активным, в режиме `QS_HEADLESS=1` F5 не работает.

Если нажимать F5 во время автоматического режима, нажатия переворачивают состояние сценария, и в сайдкаре появляются очень короткие пары `in` / `out`. Такие пары превращаются в зум-импульс примерно на секунду без удержания.

Включение и выключение переменной зависит от оболочки:

```
# PowerShell: переменная действует до закрытия окна, а не на одну команду
$env:QS_AUTO_ZOOM="0"                  # ручной режим
Remove-Item Env:QS_AUTO_ZOOM           # вернуть автоматический режим

# cmd
set QS_AUTO_ZOOM=0
set QS_AUTO_ZOOM=

# bash: на одну команду
QS_AUTO_ZOOM=0 python capture_video.py
```

Допустимые значения «выключено»: `0`, `false`, `no` (регистр не важен). То же правило у `QS_ZOOM_RING`, который скрывает кольцо-индикатор.

Для проверки ручного режима возьмите копию `input.csv` с одной строкой и укажите её через `--csv`, иначе F5 придётся нажимать на каждой записи. Если запись прошла без нажатий F5, сайдкара не будет, а на сервер видео загрузится без обработки.

### `apply_zoom.py` (запуск вручную)

Нужен установленный ffmpeg с кодировщиком `libvpx-vp9` (это не Python-пакет: установите его отдельно и добавьте в `PATH` либо укажите путь через `--ffmpeg`). На компьютере с рекордером он нужен только для ручного запуска, для обработки на сервере он уже есть в Docker-образе.

```
python apply_zoom.py --video "video/Gamma SARL.webm"
python apply_zoom.py --video "video/Gamma SARL.webm" --dry-run
python apply_zoom.py --video "video/Gamma SARL.webm" --ffmpeg C:\tools\ffmpeg\bin\ffmpeg.exe
```

| Опция            | Значение                                                                         |
| ---------------- | -------------------------------------------------------------------------------- |
| `--video PATH`   | входное видео (обязательно)                                                      |
| `--sidecar PATH` | сайдкар (по умолчанию `<видео>.zoom.json` рядом с видео)                         |
| `--output PATH`  | результат (по умолчанию `<видео>.zoomed.webm`)                                   |
| `--ffmpeg PATH`  | бинарник ffmpeg (по умолчанию переменная `FFMPEG_BIN`, иначе `ffmpeg` из `PATH`) |
| `--dry-run`      | только напечатать команду ffmpeg, ничего не кодировать                           |

Результат сначала пишется во временный файл `*.part` и переименовывается после успеха, поэтому готового, но битого файла не остаётся. Код возврата `0` при успехе, `1` при ошибке (сообщение выводится как `ERROR: ...`).

### Обработка на сервере

1. Рекордер загружает видео вместе с сайдкаром (поле `zoom`). Сервис проверяет сайдкар, сохраняет его в PostgreSQL (`zoom_sidecar`) и при `AUTO_PROCESS=1` ставит задачу в очередь (`pending`).
2. Фоновый поток внутри `web` запускает `apply_zoom.process_video` и сохраняет результат в `uploads/processed/<имя>.webm`.
3. В БД записываются `process_status`, `processed_video_url`, `processed_file_path`, `processed_at` и текст ошибки, если она была.
4. Рекордер опрашивает `GET /jobs/<id>`, выводит `Processed: <url>` и открывает в предпросмотре обработанное видео.

Особенности:

- Повторная загрузка той же компании сбрасывает результат и ставит новую задачу. Если видео перезалили во время обработки, устаревший результат отбрасывается.
- При перезапуске контейнера незавершённые задачи получают статус `failed` с текстом `interrupted by service restart`. Повторить: `POST /jobs/<id>/process`.
- Одновременно работает до `2 × ZOOM_WORKERS` ffmpeg (два процесса mod_wsgi).

## Имена файлов и кодировка

- Имя файла строится из названия компании: недопустимые символы и пробелы заменяются на `_`, буквы любых алфавитов сохраняются (`Müller & Söhne GmbH` -> `Müller_Söhne_GmbH.webm`, `ООО Ромашка` -> `ООО_Ромашка.webm`).
- Если два названия дают одно имя файла, второму добавляется хеш (`Acme_Web_Dev_88158e08.webm`), записи не затирают друг друга.
- Файлы сохраняются в **UTF-8**. Для этого в `docker/apache/videos.conf` процессам mod_wsgi задана локаль `C.UTF-8` (`lang` и `locale` в `WSGIDaemonProcess`). Без неё Apache работает с локалью `C` (ASCII), и загрузка файлов с не-ASCII именами падает с ошибкой 500.
- В ссылках имена кодируются (`M%C3%BCller_S%C3%B6hne_GmbH.webm`).
- `input.csv` должен быть в UTF-8 (допускается BOM).

## Рекордер (на вашем компьютере)

Требования: Python 3.9+.

```
pip install -r requirements.txt
python -m playwright install chromium
```

Запуск:

```
python capture_video.py
python capture_video.py --csv input.csv --out ./video
python capture_video.py --server http://localhost:8000 --view-seconds 5
python capture_video.py --server http://localhost:8000 --process-timeout 0
```

Видео сохраняются в `./video` под именем `<Company Name>.webm` (недопустимые для Windows символы заменяются на `_`), рядом при наличии zoom-событий лежит `<Company Name>.webm.zoom.json`. Для каждой строки выводится `[N] Saved: <путь>`.

| Опция                 | Значение                                                                                                              |
| --------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `--csv PATH`          | входной CSV (по умолчанию `input.csv`)                                                                                |
| `--out DIR`           | папка для видео (по умолчанию `./video`)                                                                              |
| `--server URL`        | если задан, каждое видео (и сайдкар) загружается на сервис, обрабатывается и открывается в Chromium                   |
| `--view-seconds N`    | сколько секунд держать окно предпросмотра (по умолчанию 10). `0` — до нажатия Enter в терминале, где запущен рекордер |
| `--process-timeout N` | сколько секунд ждать zoom-обработку каждого видео (по умолчанию 300). `0` — не ждать, превью оригинала                |

Без `--server` сервис не нужен. Ошибка записи, загрузки, обработки или предпросмотра не останавливает обработку: строка выводится как `FAILED`, `UPLOAD FAILED` или `PROCESS FAILED` (при сбое обработки превью открывается по оригиналу), и скрипт переходит к следующей. Код возврата `0`, если все строки записаны и загружены, иначе `1`; сбой обработки на код возврата не влияет.

### Формат `input.csv`

Кодировка UTF-8, разделитель `;`, ограничитель полей `"`. Заголовок:

```
URL;Company Name;Language;Country;Postcode;City;Street;HouseNo
```

В запросе используется значение `City` (если оно пустое, запрос будет `Magento developer`). Из `Language` берётся локаль браузера, некорректное значение игнорируется.

В `input.csv` из репозитория часть строк **намеренно некорректна** (несуществующий домен, URL без схемы, пустой URL, сайт без поля поиска DuckDuckGo) и служит для проверки обработки ошибок. Для такого файла рекордер завершится с кодом `1`, ожидаемый итог при запуске с `--server`: `Done: 8 of 12 videos saved. Uploaded: 8 of 8.` и следом `Zoom processed: 8 of 8.`

### Переменные окружения рекордера (необязательные)

| Переменная                               | Значение                                             |
| ---------------------------------------- | ---------------------------------------------------- |
| `QS_HEADLESS=1`                          | запуск без окна браузера (по умолчанию окно видно)   |
| `QS_BROWSER_CHANNEL=chrome` или `msedge` | использовать установленный Chrome или Edge           |
| `QS_DEBUG=1`                             | при сбое сохранять скриншот и видео неудачной записи |
| `QS_AUTO_ZOOM=0`                         | сценарий сам не включает зум (остаётся ручной F5)    |
| `QS_ZOOM_RING=0`                         | не показывать кольцо-индикатор переключения зума     |

PowerShell: `$env:QS_HEADLESS="1"`. На Linux без графической среды: `xvfb-run -a python capture_video.py`.

### Примечания

- DuckDuckGo может блокировать автоматические запросы (страница ошибки 418), особенно в режиме без окна или при частых запусках. Подождите, смените сеть или запустите с видимым окном. При ошибке страницы скрипт перезагружает её до двух раз.
- Рекордер рассчитан на текущие селекторы DuckDuckGo, они заданы константами в начале `qscript.py`.
- Разовые сетевые ошибки Chromium (например `ERR_CERT_VERIFIER_CHANGED`) приводят к `FAILED` для строки. Повторите запуск.

## Клиент (`video_client.py`)

| Функция                                               | Назначение                                                                       |
| ----------------------------------------------------- | -------------------------------------------------------------------------------- |
| `UploadVideo(server_url, video_path, company_name)`   | загружает видео (и сайдкар, если он лежит рядом) и возвращает его URL            |
| `UploadVideoEx(server_url, video_path, company_name)` | то же, но возвращает ответ сервера целиком (`video_url`, `id`, `process_status`) |
| `GetVideoURL(server_url, company_name)`               | возвращает URL видео компании, `LookupError` если не найдено                     |
| `ProcessVideo(server_url, job_id)`                    | запускает обработку; `409` (уже идёт) ошибкой не считается                       |
| `GetJobStatus(server_url, job_id)`                    | статус задачи: `status`, `error`, `processed_video_url`                          |
| `WaitForJob(server_url, job_id, timeout, interval)`   | ждёт `done` или `failed`, `TimeoutError` по истечении времени                    |
| `find_zoom_sidecar(video_path)`                       | путь к `<видео>.zoom.json` рядом с видео или `None`                              |

## Тесты

```

```

Эта команда запускает юнит-тесты (формулы и фильтр zoompan, разбор сайдкара, путь «нет событий — копия», `--dry-run`, захват событий). Им не нужны ни Docker, ни ffmpeg, ни сеть. Интеграционные тесты по умолчанию пропускаются.

```
# bash
RUN_DOCKER_TESTS=1 pytest -m integration -v
```

Необязательные переменные: `SERVER_URL` (по умолчанию `http://localhost:8000`) и `PROCESS_TIMEOUT` (секунд, по умолчанию 300). Интеграционные тесты оставляют в БД и в томе `uploads` записи с именами `it-*`.

## Компании и Impressum

Скрипт `enrich_companies.py` загружает сайты компаний из PostgreSQL, находит страницу Impressum / Imprint, извлекает юридические данные через DeepSeek API и записывает результат обратно в БД. Запуск — внутри контейнера `web`.

### Подготовка

1. Добавьте ключ DeepSeek в `.env`:
   ```
   DEEPSEEK_API_KEY=sk-...
   DEEPSEEK_MODEL=deepseek-chat
   ```
2. Пересоберите и запустите стек:
   ```
   docker compose up --build
   ```
3. Загрузите CSV через форму [http://localhost:8000/upload_companies](http://localhost:8000/upload_companies) или через curl (см. ниже).

### Формат CSV

UTF-8, разделитель `;`, ограничитель `"`. Обязательные колонки: `Company Name` и `Web`. Остальные сохраняются как есть.

```
URL;Company Name;Language;Country;Postcode;City;Street;HouseNo;Web
"";"nutrimmun GmbH";"";"";"";"";"";"";"https://nutrimmun.de/"
"";"Barolo & Champagne GbR";"";"";"";"";"";"";"https://www.baroloandchampagne.com/"
```

Повторный импорт обновляет только CSV-колонки (`language`, `country`, `postcode`, `city`, `street`, `house_no`, `web`). Результаты обогащения (`status`, `legal_name`, `postal_address`, `raw_json` и др.) **не затираются**.

### Запуск обогащения

```
docker compose exec web python enrich_companies.py [опции]
```

| Опция              | Значение                                           |
| ------------------ | -------------------------------------------------- |
| `--company "NAME"` | обработать только эту компанию (при любом статусе) |
| `--limit N`        | не более N строк                                   |
| `--status N`       | только строки с этим статусом (0–5)                |
| `--force`          | включить в выборку уже успешные строки (статус 0)  |
| `-v`               | подробный вывод (DEBUG)                            |

По умолчанию обрабатываются все строки со статусом `NULL` (не обработано) или отличным от `0` (OK). Строки со статусом `5` (NO_WEBSITE) переобрабатываются при каждом запуске — это дёшево, сетевых запросов нет.

Примеры:

```
# Все необработанные
docker compose exec web python enrich_companies.py

# Одна конкретная компания
docker compose exec web python enrich_companies.py --company "nutrimmun GmbH"

# Переобработать только ошибки, не более 10
docker compose exec web python enrich_companies.py --status 4 --limit 10

# Принудительно переобработать всё
docker compose exec web python enrich_companies.py --force
```

Код возврата `0` — выборка обработана (даже если есть статусы 1–5). Ненулевой — нет ключа API или БД недоступна.

### Статусы компаний

| Код  | Имя                     | Когда выставляется                                                   |
| ---- | ----------------------- | -------------------------------------------------------------------- |
| NULL | _(не обработано)_       | свежий импорт, обогащение ещё не запускалось                         |
| 0    | OK                      | данные извлечены, адрес полный (postcode + city + street + house_no) |
| 1    | NO_IMPRESSUM_LINK_FOUND | на главной странице нет ссылки на Impressum / Imprint                |
| 2    | PARSING_FAILED          | Impressum найден, но DeepSeek не извлёк ни одного поля               |
| 3    | ADDRESS_INCOMPLETE      | поля извлечены, но адрес неполный                                    |
| 4    | ERROR                   | сеть, HTTP 4xx/5xx, ошибка API (включая 401); пакет продолжается     |
| 5    | NO_WEBSITE              | колонка `web` пуста                                                  |

Отсутствие VAT, телефона или имени директора **не понижает** статус. Если адрес полный — это OK.

### Токен-оптимизация

Impressum-страницы содержат навигацию, cookie-баннеры, футеры. Перед отправкой в API текст оптимизируется:

1. Удаляются шумовые строки (Datenschutz, AGB, Menü, языки, ©).
2. Находится головной якорь (`Impressum`, `Angaben gemäß § 5 TMG/DDG`) и последний сильный сигнал (телефон `+49`, НДС `DE\d{9}`, e-mail, HRB/HRA, Geschäftsführer).
3. Текст обрезается до окна между якорями («сэндвич»). Если окно длиннее 8000 символов — фильтр по ключевым словам, затем head+tail window.
4. Cloudflare `data-cfemail` декодируется автоматически.

В логе видно экономию:

```
nutrimmun GmbH: 4954 -> 4954 chars (~1238 -> ~1238 tokens), strategy=unchanged
Barolo & Champagne GbR: 8990 -> 5484 chars (~2247 -> ~1371 tokens), tail cut 3433, strategy=sandwich
```

### Эндпоинты компаний

| Метод и путь                    | Назначение                                                            |
| ------------------------------- | --------------------------------------------------------------------- |
| `GET /upload_companies`         | HTML-форма загрузки CSV                                               |
| `POST /upload_companies`        | импорт CSV, ответ: `{"imported", "updated", "total_rows"}`            |
| `GET /companies`                | список всех компаний (JSON), фильтр `?status=N` или `?status=pending` |
| `GET /companies/<company_name>` | одна компания (JSON), 404 если нет                                    |

### Примеры curl

```bash
# Загрузить CSV
curl -F "file=@companies.csv" http://localhost:8000/upload_companies

# Список всех компаний
curl http://localhost:8000/companies

# Только необработанные
curl "http://localhost:8000/companies?status=pending"

# Одна компания (имя с пробелами и спецсимволами кодируется)
curl "http://localhost:8000/companies/nutrimmun%20GmbH"

# Компания с & в названии
curl "http://localhost:8000/companies/Barolo%20%26%20Champagne%20GbR"
```

В PowerShell используйте `curl.exe`.

### Postman

- `POST /upload_companies`: Body → `form-data`, поле `file` (тип File, выбрать `.csv`). Заголовок `Content-Type` не задавайте.
- `GET /companies`: без параметров или Params: `status` = `0` / `pending`.
- `GET /companies/{name}`: имя в URL кодируйте (`%20`, `%26`). Конвертер `<path:...>` принимает `/` в имени.

### Принятые допущения

- Сайты, где ссылка на Impressum рендерится JavaScript-ом и отсутствует в сыром HTML, получают статус `1`. Playwright-fallback не реализован в первой версии.
- Отступы сэндвича уменьшены относительно рекомендации ТЗ (§5 п.4 «Enlarge margins») — на реальных немецких Impressum меньшие отступы дают лучший результат без потери данных.
- Ключ `DEEPSEEK_API_KEY` читается из окружения и никогда не логируется. Не коммитьте `.env`.

## Частые проблемы

| Симптом                                                     | Причина и решение                                                                                                            |
| ----------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `Executable doesn't exist ... chrome.exe`                   | не установлен браузер: `python -m playwright install chromium`                                                               |
| `exec ... no such file or directory` при старте `web`       | в `docker/entrypoint.sh` переводы строк CRLF: приведите к LF                                                                 |
| `ModuleNotFoundError: No module named 'apply_zoom'` в `web` | образ собран до добавления файла: `docker compose up --build`                                                                |
| `password authentication failed`                            | пароль изменён после создания тома: `docker compose down -v`                                                                 |
| 500 с `'ascii' codec can't encode` при загрузке             | не применён `lang`/`locale` в `videos.conf`: пересоберите `docker compose up --build`                                        |
| порт `8000` занят                                           | освободите порт или измените левую часть `8000:80` в `docker-compose.yml`                                                    |
| рекордер: `UPLOAD FAILED`                                   | сервис не запущен или неверный адрес в `--server`                                                                            |
| рекордер: `PROCESS FAILED: server did not return a job id`  | запущена старая версия сервиса: `docker compose up --build`                                                                  |
| `POST /upload` вернул 400 `Invalid zoom sidecar`            | сайдкар не соответствует формату (см. раздел «Zoom-эффект»)                                                                  |
| статус `failed`                                             | причина в поле `error` у `GET /jobs/<id>` и в `docker compose logs web`; повтор: `POST /jobs/<id>/process`                   |
| `interrupted by service restart`                            | контейнер перезапускали во время обработки; повторите `POST /jobs/<id>/process`                                              |
| `apply_zoom.py`: `ffmpeg not found`                         | установите ffmpeg и добавьте в `PATH` либо укажите `--ffmpeg <путь>`                                                         |
| в видео нет зума                                            | нет `<видео>.webm.zoom.json` (запись с `QS_AUTO_ZOOM=0` без нажатий F5) или видео не обработано                              |
| F5 не включает зум                                          | в headless клавиатуры нет, окно браузера должно быть активным; используйте `window.__zoomAt`                                 |
| DuckDuckGo показывает ошибку 418                            | временная блокировка: подождите, смените сеть, запустите с окном                                                             |
| автозум пропал, зум не включается сам                       | в этом окне PowerShell осталась `QS_AUTO_ZOOM=0`: `Remove-Item Env:QS_AUTO_ZOOM` или новое окно                              |
| зум включается и сразу пропадает                            | F5 нажимали во время автоматического режима: используйте один режим (см. «Автоматический и ручной режим зума»)               |
| `pytest -v` запускает и юнит-тесты, и интеграционные тесты  | Осталась переменная `RUN_DOCKER_TESTS` в терминале, пропишите `Remove-Item Env:RUN_DOCKER_TESTS` или откройте новый терминал |

Проверка внутри контейнера: `docker compose exec web curl http://localhost/videos`, `docker compose exec web ffmpeg -version`, логи: `docker compose logs -f web`.
