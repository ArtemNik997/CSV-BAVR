# CSV-driven Browser Automation Video Recorder

Для каждой строки входного CSV инструмент (Python + Playwright) записывает видео автоматизированных действий в браузере: открывает DuckDuckGo, плавно ведёт курсор к полю поиска, посимвольно вводит запрос `Magento developer in <City>`, нажимает поиск и кликает по первому результату. В видео добавлены SVG-курсор, подсветка, ripple при кликах и callout с текстом.

Записанные видео можно загрузить на веб-сервис. Сервис (Flask + Apache/mod_wsgi) и база данных (PostgreSQL) работают в отдельных Docker-контейнерах и запускаются вместе через Docker Compose.

## Архитектура

| Часть                                       | Где работает        | Назначение                                                 |
| ------------------------------------------- | ------------------- | ---------------------------------------------------------- |
| Рекордер (`capture_video.py`, `qscript.py`) | на вашем компьютере | запись видео, загрузка на сервис, предпросмотр             |
| `web`                                       | контейнер           | Apache + mod_wsgi, Flask-сервис видео, порт `8000` -> `80` |
| `db`                                        | контейнер           | PostgreSQL 16, таблица `videos`                            |

Тома: `db_data` (данные PostgreSQL) и `uploads` (загруженные видео). Они сохраняются при перезапуске контейнеров.

## Запуск веб-сервиса и БД в Docker

Требуется Docker и Docker Compose v2.

```
docker compose up --build
```

Сервис доступен на `http://localhost:8000`. Остановка: `Ctrl+C` или `docker compose down`.

Пароль и имя базы по умолчанию (`video_user` / `video_pass` / `videos`) подходят для учебного запуска. Для своих значений:

```
cp .env.example .env
```

и измените значения в `.env`. Файл `.env` в Git не коммитится.

| Переменная (`.env`) | По умолчанию | Назначение   |
| ------------------- | ------------ | ------------ |
| `POSTGRES_DB`       | `videos`     | имя базы     |
| `POSTGRES_USER`     | `video_user` | пользователь |
| `POSTGRES_PASSWORD` | `video_pass` | пароль       |

Из этих значений Compose передаёт контейнеру `web` настройки подключения `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASSWORD`. В коде они не заданы.

**Данные и тома**

- `docker compose down` — контейнеры удаляются, данные и видео **сохраняются**.
- `docker compose down -v` — тома удаляются вместе с данными.
- Пароль из `.env` применяется только при первой инициализации пустого тома `db_data`. После смены пароля на существующей БД выполните `docker compose down -v` (данные будут удалены).

**Готовность БД.** `web` стартует только после успешной проверки `db` (`healthcheck`, `depends_on: service_healthy`). Дополнительно `init_db()` до 60 раз (с паузой 2 с) пробует подключиться и создаёт таблицу `videos`.

## Эндпоинты

| Метод и путь                                 | Назначение                                                                                 |
| -------------------------------------------- | ------------------------------------------------------------------------------------------ |
| `POST /upload`                               | multipart-форма: `file` и `company_name`. Ответ: `{"company_name": ..., "video_url": ...}` |
| `GET /get_video_url?company_name=<название>` | URL видео компании, 404 если компании нет                                                  |
| `GET /media/<имя файла>`                     | видеофайл (отдаёт Apache, поддерживает перемотку)                                          |
| `GET /videos`                                | список всех записей (для отладки)                                                          |

Повторная загрузка той же компании обновляет запись и файл, дубликаты не создаются. Время в БД хранится в UTC (`TIMESTAMPTZ`).

```
curl -F "file=@video/Beta Solutions.webm" -F "company_name=Beta Solutions" http://localhost:8000/upload
curl "http://localhost:8000/get_video_url?company_name=Beta%20Solutions"
```

В PowerShell используйте `curl.exe`.

## Имена файлов и кодировка

- Имя файла строится из названия компании: недопустимые символы и пробелы заменяются на `_`, буквы любых алфавитов сохраняются (`Müller & Söhne GmbH` -> `Müller_Söhne_GmbH.webm`, `ООО Ромашка` -> `ООО_Ромашка.webm`).
- Если два названия дают одно имя файла, второму добавляется хеш (`Acme_Web_Dev_88158e08.webm`), записи не затирают друг друга.
- Файлы сохраняются в **UTF-8**. Для этого в `docker/apache/videos.conf` процессам mod_wsgi задана локаль `C.UTF-8` (`lang` и `locale` в `WSGIDaemonProcess`). Без неё Apache работает с локалью `C` (ASCII), и загрузка файлов с не-ASCII именами падает с ошибкой 500.
- В ссылках имена кодируются (`M%C3%BCller_S%C3%B6hne_GmbH.webm`).
- `input.csv` должен быть в UTF-8 (допускается BOM).

## Рекордер (на вашем компьютере)

Требования: Python 3.9+.

```
pip install -r requirements.txt
python -m playwright install chromium
```

Запуск:

```
python capture_video.py
python capture_video.py --csv input.csv --out ./video
python capture_video.py --server http://localhost:8000 --view-seconds 5
```

Видео сохраняются в `./video` под именем `<Company Name>.webm` (недопустимые для Windows символы заменяются на `_`). Для каждой строки выводится `[N] Saved: <путь>`.

| Опция              | Значение                                                                                                              |
| ------------------ | --------------------------------------------------------------------------------------------------------------------- |
| `--csv PATH`       | входной CSV (по умолчанию `input.csv`)                                                                                |
| `--out DIR`        | папка для видео (по умолчанию `./video`)                                                                              |
| `--server URL`     | если задан, каждое видео загружается на сервис и открывается в Chromium                                               |
| `--view-seconds N` | сколько секунд держать окно предпросмотра (по умолчанию 10). `0` — до нажатия Enter в терминале, где запущен рекордер |

Без `--server` сервис не нужен. Ошибка записи, загрузки или предпросмотра не останавливает обработку: строка выводится как `FAILED`, и скрипт переходит к следующей. Код возврата `0`, если все строки обработаны, иначе `1`.

### Формат `input.csv`

Кодировка UTF-8, разделитель `;`, ограничитель полей `"`. Заголовок:

```
URL;Company Name;Language;Country;Postcode;City;Street;HouseNo
```

В запросе используется значение `City` (если оно пустое, запрос будет `Magento developer`). Из `Language` берётся локаль браузера, некорректное значение игнорируется.

В `input.csv` из репозитория часть строк **намеренно некорректна** (несуществующий домен, URL без схемы, пустой URL, сайт без поля поиска DuckDuckGo) и служит для проверки обработки ошибок. Для такого файла рекордер завершится с кодом `1`, ожидаемый итог: `Done: 8 of 12 videos saved. Uploaded: 8 of 8.`

### Переменные окружения рекордера (необязательные)

| Переменная                               | Значение                                             |
| ---------------------------------------- | ---------------------------------------------------- |
| `QS_HEADLESS=1`                          | запуск без окна браузера (по умолчанию окно видно)   |
| `QS_BROWSER_CHANNEL=chrome` или `msedge` | использовать установленный Chrome или Edge           |
| `QS_DEBUG=1`                             | при сбое сохранять скриншот и видео неудачной записи |

PowerShell: `$env:QS_HEADLESS="1"`. На Linux без графической среды: `xvfb-run -a python capture_video.py`.

### Примечания

- DuckDuckGo может блокировать автоматические запросы (страница ошибки 418), особенно в режиме без окна или при частых запусках. Подождите, смените сеть или запустите с видимым окном. При ошибке страницы скрипт перезагружает её до двух раз.
- Рекордер рассчитан на текущие селекторы DuckDuckGo, они заданы константами в начале `qscript.py`.
- Разовые сетевые ошибки Chromium (например `ERR_CERT_VERIFIER_CHANGED`) приводят к `FAILED` для строки. Повторите запуск.

## Структура проекта

| Файл                        | Назначение                                                                                    |
| --------------------------- | --------------------------------------------------------------------------------------------- |
| `capture_video.py`          | читает CSV, вызывает `qscript.CaptureVideo_Magento`, загружает видео и открывает предпросмотр |
| `qscript.py`                | запись видео, визуальные эффекты                                                              |
| `video_client.py`           | клиент веб-сервиса                                                                            |
| `web_service.py`            | Flask-сервис на PostgreSQL (`psycopg2`)                                                       |
| `app.wsgi`                  | точка входа mod_wsgi (`from web_service import app as application`)                           |
| `Dockerfile`                | образ Apache + mod_wsgi + Flask на Debian                                                     |
| `docker-compose.yml`        | сервисы `web` и `db`, тома, healthcheck                                                       |
| `docker/apache/videos.conf` | VirtualHost, WSGI, раздача `/media/` через `Alias`                                            |
| `docker/entrypoint.sh`      | ожидание БД, создание таблицы, запуск Apache                                                  |
| `.env.example`              | шаблон переменных (без реальных паролей)                                                      |
| `.dockerignore`             | что не попадает в контекст сборки                                                             |
| `requirements.txt`          | зависимости (`playwright`, `flask`, `requests`, `psycopg2-binary`)                            |
| `input.csv`                 | пример входных данных                                                                         |

## Частые проблемы

| Симптом                                               | Причина и решение                                                                     |
| ----------------------------------------------------- | ------------------------------------------------------------------------------------- |
| `Executable doesn't exist ... chrome.exe`             | не установлен браузер: `python -m playwright install chromium`                        |
| `exec ... no such file or directory` при старте `web` | в `docker/entrypoint.sh` переводы строк CRLF: приведите к LF                          |
| `password authentication failed`                      | пароль изменён после создания тома: `docker compose down -v`                          |
| 500 с `'ascii' codec can't encode` при загрузке       | не применён `lang`/`locale` в `videos.conf`: пересоберите `docker compose up --build` |
| порт `8000` занят                                     | освободите порт или измените левую часть `8000:80` в `docker-compose.yml`             |
| рекордер: `UPLOAD FAILED`                             | сервис не запущен или неверный адрес в `--server`                                     |
| DuckDuckGo показывает ошибку 418                      | временная блокировка: подождите, смените сеть, запустите с окном                      |

Проверка внутри контейнера: `docker compose exec web curl http://localhost/videos`, логи: `docker compose logs -f web`.
